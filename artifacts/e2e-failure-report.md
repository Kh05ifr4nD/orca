## Diagnosis and validation

- **Test maintenance:** The native-chat rail implementation focuses the prompt marked current, and the reveal dialog now adjusts filters while retaining the previous repository selection. The changed tests assert those contracts. The pointer spec previously compared Chromium event dispatch with a near-zero-cost eval call: original CI measured control 4.625 ms, move 15.392 ms, wheel 568.067 ms, and four-event click 2033.158 ms; pinned-SHA Linux replay measured 0.758, 15.958, 16.667, and 191.700 ms. The control ratio failed on both, while a local diagnostic passed click, double click, right click, drag, and wheel checks. The patch checks mouse move and wheel against a 100 ms responsiveness budget, requires the click pair inside Chromium's 500 ms double-click window, and still requires the `dblclick` event. Three consecutive patched Linux runs had click pairs of 1,961/1,978/4,061 ms and press gaps of 934/1,950/2,033 ms. The bulk latency measurement used blank-page coordinates while the gesture clicked a real button; the exact source of the stall needs investigation. The test remains enabled.
- **Repository infrastructure:** The legacy-close fixture constructed `OrcaRuntimeService` without the Orcad host adapters and Store it expects. The local fixture patch supplies both using disposable data. The original false close result was reproduced before editing, and a fresh app launch after the patch passed.
- **Product regressions:** Rows 2, 3, 4, and 9 repeated on the exact original SHA under Ubuntu 24.04. Row 5 reproduced on macOS and remained after a render-frame timing probe. Row 10 failed on the patched Linux branch after its invalid comparison was replaced by gesture checks. These tests remain enabled. Existing matching issues received fresh evidence after duplicate searches by test name and symptom; no new product issue was opened. The requested plural `test-detected-bugs` label was not present in the connected Linear workspace; existing issues use `test-detected-bug`.
- **Intermittent cases:** Rows 1, 11, and 12 each passed in three consecutive Ubuntu 24.04 replays of the original SHA: [35968483482](https://github.com/stablyai/orca/actions/runs/35968483482), [35969397086](https://github.com/stablyai/orca/actions/runs/35969397086), and [35969914377](https://github.com/stablyai/orca/actions/runs/35969914377). In the full original-SHA sharded replay, row 1 passed again while rows 11 and 12 failed again with zero lookup and missing suggestion. The source-control patch avoids the observed mouse click stability wait by activating the enabled button from keyboard focus; a separate test in the file still covers mouse activation. The URL patches wait for the visible repo-backed Project selection before triggering a GitHub lookup. The three original failures are test timing behavior, with no independent product assertion. The patched cases and both spec files passed three consecutive Ubuntu runs.
